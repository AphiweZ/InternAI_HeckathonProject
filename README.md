# InternAI

An AI-powered internship agent that helps students find, evaluate, and apply for internships based on their skills, location, and career goals. Built for an Agentic AI hackathon.

## What it does

A student uploads their CV → the agent analyses their skills → matches them against available internships → ranks the best-fit opportunities → generates a tailored cover letter → and the student can track their applications and deadlines, all in one place.

## Tech stack

- ASP.NET MVC (.NET Framework)
- C#
- Newtonsoft.Json (for reading the mock internship dataset)
- Razor views (`.cshtml`)

## Two halves of the project

This project is split into two parallel workstreams, joined by one shared contract:

| Half | Owns | Status |
|---|---|---|
| **Agent/AI core** | CV analysis, matching/ranking logic, cover letter generation, conversational Q&A | Built separately (Partner A) |
| **Product shell** | Internship listing UI, application tracker, deadline highlighting, CV upload UI | Built in this repo (Partner B) |

**The contract:** any AI implementation must satisfy this interface:

```csharp
public interface IAgentService
{
    List<RankedInternship> AnalyzeAndMatch(CvData cv, List<Internship> internships);
}
```

As long as a class implements `IAgentService` with that exact method signature, it can be swapped in for the temporary `AgentServiceStub` with a one-line change in `UploadController.cs`.

## How to run it

1. Open `InternAI_HeckathonProject.sln` in Visual Studio.
2. Restore NuGet packages if prompted (or run `Install-Package Newtonsoft.Json` in the Package Manager Console if it's missing).
3. Press **F5** to build and run.
4. Use the navbar to move between pages, or visit directly:
   - `/Internships` — browse available internships
   - `/Tracker` — view and manage tracked applications
   - `/Upload` — upload a CV and see matched results

## User flow

1. Student browses `/Internships`, sees mock listings loaded from `internships.json`.
2. Clicking **Track this** adds the internship to an in-memory application tracker.
3. `/Tracker` shows tracked applications, with rows highlighted red (≤3 days) or yellow (≤7 days) based on deadline urgency, and a dropdown to update status (Not Applied / Applied / Interview / Rejected / Offer).
4. Student uploads a CV at `/Upload`.
5. The app builds a `CvData` object, loads the internship list, and calls `IAgentService.AnalyzeAndMatch` to get a ranked `List<RankedInternship>`.
6. `/Upload/Results` (reachable only by submitting the form) displays each internship with match score, matched/missing skills, and a cover letter — sorted best match first.

## Known limitations

- Tracked applications live in a static in-memory list and reset when the app restarts. A real database (e.g. SQLite/SQL Server + Entity Framework) would be needed for persistence beyond a demo.
- `/Upload/Results` has no standalone route — it only renders as the result of submitting the upload form, so visiting it directly or refreshing on it returns a 404.
- CV "analysis" is currently a placeholder — the uploaded file's contents aren't read yet; only the file name is used.
- Match scores are currently randomly generated by `AgentServiceStub`, not a real evaluation of fit.
